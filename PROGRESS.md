## Findings worth remembering

- With the laptop idle (display off), Chrome may report a page visible and focused yet drop CDP mouse events entirely; keyboard events still arrive. Never trust a click without checking it landed (`press()` in browser.mjs).

- Claude Code here runs inside the Claude desktop app's package: its writes under `AppData` land in `…\Packages\Claude_…\LocalCache`, invisible to Windows itself. A shortcut made that way pointed at a file that did not exist outside the package. Anything AYRA installs for the owner lives on E: (`desktop/bin/`); check the real view with a script run through `explorer.exe`.
- `taskkill /T` follows parent PIDs, so `detached: true` children (her Chrome) die with the tree. Stop processes by closing their input instead.
- A key sent with `keybd_event` and no scan code reaches Chrome with `KeyboardEvent.code === ""`; pass `MapVirtualKey`'s scan code.

- UI Automation on this laptop: cache the whole window in one `GetUpdatedCache(Subtree)` call (a property-by-property walk is ~10× slower); `InvokePattern.Invoke()` does not return while a modal dialog it opened is up, so run it in a separate runspace; Windows PowerShell 5.1 reads a `.ps1` without BOM in the local code page — keep `bridge/apps.ps1` ASCII.
- Win11 Notepad restores its last tabs — here that included `.env.local`, which is why window reads refuse files of secrets. Launching Notepad while one is open opens a second window.
